# 백엔드 확인용 프롬프트 — 깊이형(지중경사계) measurements 처리 준비 여부

> 아래 블록을 그대로 복사해 백엔드에 전달하세요. (펄스가 보낼 형식을 백엔드가 그대로 받을/저장할/보여줄 준비가 됐는지 확인)

---

## [펄스 → 백엔드 확인] 깊이형(지중경사계) ingest 처리 준비됐나요?

### 배경 — 지중경사계 데이터 구조
지중경사계(inclinometer)는 땅에 박은 관 1개가 **깊이마다(0.5m 간격) 변위를 재는** 장비입니다.
- 그래서 .txt 헤더가 깊이 = `"DateTime","0.0M","0.5M", … ,"40.0M"` (81개 깊이).
- **한 시각(한 줄) = 깊이 0~40m를 쭉 잰 81개 값**.
- 이건 센서 81개가 아니라 **장비 1대(센서 1개)**가 깊이별로 찍은 것.

### 펄스가 보내는 형식 (확정)
- 센서 **1개** (`sensorCode = "{node_code}-A"`, 예 `지중경사계_(I-4-AB)-A`).
- 깊이는 sensorCode 가 아니라 **각 measurement 의 `depthLabel`**.
- 한 시각의 81개 깊이 = **같은 `measuredAt` + 다른 `depthLabel`** measurement 81개.

```
POST /api/pulse/v1/ingest
{
  "sensorCode": "지중경사계_(I-4-AB)-A",
  "measurements": [
    { "measuredAt": "2026-06-02T09:00:00.000Z", "value": 1.20, "depthLabel": "0.0M" },
    { "measuredAt": "2026-06-02T09:00:00.000Z", "value": 1.21, "depthLabel": "0.5M" },
    { "measuredAt": "2026-06-02T09:00:00.000Z", "value": 1.22, "depthLabel": "1.0M" },
    ... (0.0M ~ 40.0M, 총 81건, 모두 measuredAt 동일)
  ]
}
```
(시각이 여러 개면 시각 × 81건이 한 요청에 들어옵니다.)

### 확인 질문 (이게 핵심)
1. **depthLabel 저장**: measurement 에 `depthLabel` 필드를 **저장**하나요? (스키마에 있나요, 아니면 무시되나요?)
2. **같은 시각 81건 보존**: **measuredAt 이 같고 depthLabel 만 다른 81건**을, 시각 기준으로 덮어쓰거나 합치지 않고 **81개 그대로 보존**하나요? (깊이별로 다 남아야 함)
3. **조회/표시**: 깊이별 값을 되돌려 줄 수 있나요? (웹에서 "깊이 vs 값" 프로파일 차트로 보여줄 준비가 됐나요?)
4. **단위**: 이 값들의 단위는 무엇으로 저장되나요? (인클리노미터 변위 mm 등 — 카탈로그 기본/노드 unit/그대로?)
5. **depthLabel 형식**: `"0.0M"` 같은 문자열 그대로 받나요, 아니면 숫자(미터)로 파싱이 필요한가요? 필요하면 펄스가 맞추겠습니다.

### 수용 기준 (이러면 OK)
- 81건이 1개 센서(`-A`)에 **깊이별로 다 저장**되고, 같은 시각이어도 81개가 보존됨.
- 조회 시 (시각, 깊이, 값) 세트로 되돌아옴.

### 참고
- 현재 지중경사계 .txt 2개는 **헤더만 있고 데이터 0줄**이라 아직 ingest 된 게 없습니다(그래서 measurements 0건은 정상). 실제 값이 채워지면 위 형식대로 전송됩니다.
- sensorCode 매칭은 이미 확인됨: 펄스가 보내는 값 = 등록된 `지중경사계_(I-4-AB)-A` 와 글자 그대로 일치.
- 위 1~3 중 **안 되는 게 있으면**(특히 2번 — 같은 시각 81건 보존) 알려주세요. depthLabel 없이 시각만으로 저장하면 81개가 1개로 뭉개집니다.
