# Pulse 데스크톱 앱 — 견적 산정용 기술 총정리

> **이 문서의 용도**: 견적서 작성 LLM에 입력하는 **Pulse(현장 PC 수집기) 단독** 기술/범위 자료.
> 프론트엔드·백엔드는 별도 견적이며, 이 문서는 **Pulse 데스크톱 앱 작업분만** 다룬다.
> 모든 "완료/미완료" 표기는 실제 코드 기준(2026-06)이며, **이미 구현된 항목은 견적에서 제외**, **🚧 잔여 항목이 견적 대상**이다.
> 자기완결 문서로 작성됨 — 다른 컨텍스트 없이 이 문서만으로 범위 파악 가능.

---

## 1. 제품 개요 & 시스템 내 위치

- **제품**: Pulse — 유현건설 계측 모니터링 시스템의 **현장/사무실 PC 수집기**.
- **형태**: Windows 설치형 데스크톱 앱 (Electron). Slack/VS Code/Notion과 동일 형태.
- **역할**: 타사 로거가 사무실 PC에 떨궈주는 센서 측정 `.txt` 파일을 읽어 **검증 후 백엔드로 전송** + 로컬 모니터링 UI 제공.
- **시스템 3트랙 중 1트랙**:
  ```
  현장 로거 → [.txt 워치 폴더] → ★Pulse(본 견적)★ → 백엔드(별도 견적) → 웹 프론트(별도 견적)
  ```
- **설계 원칙 — 현장-블라인드(v2, ADR-0010)**: Pulse는 현장(Site)을 모른다. **노드(장비 ID) 단위**로만 수집·전송. 전송 페이로드에 현장 필드 없음. 현장 배치·안전 판정은 백엔드/웹 책임. (Pulse는 백엔드가 내려준 현장명을 **읽기 전용 표시**만)
- **품질 판정 위치**: 이상치·결측·보정·단위변환은 **백엔드 전담**. Pulse는 raw 정직 전송 + 운영자 입력값(정상범위/생명주기) 전달만.

## 2. 아키텍처

### 2.1 프로세스 구조 (Electron 표준 3계층)

| 계층 | 파일 | 역할 |
|---|---|---|
| **Main 프로세스** | `src/main.js`, `src/folderService.js` | Node 환경. 파일시스템 접근, IPC 핸들러, 백엔드 HTTP 호출(API키 보관) |
| **Preload 브리지** | `src/preload.js` | `window.electronAPI` 로 안전하게 기능 노출(contextIsolation) |
| **Renderer(UI)** | `src/**/*.jsx` (React) | 화면. IPC를 통해서만 시스템 자원 접근 |

### 2.2 데이터 흐름

```
타사 로거가 .txt 덮어쓰기(append 아님)
   → [워치 폴더]  (사용자가 설정에서 지정)
   → Main: scanFolder/analyzeFile (파일 구조 파싱)
   → Renderer: 노드 등록(열→센서 해석) / 모니터링
   → Main: POST /nodes(등록), POST /ingest(측정, 증분)
   → 백엔드
```

### 2.3 상태 관리 & 영속성 (현재)

- 상태: `src/lib/store.jsx` — React Context + `useState` (외부 상태 라이브러리 없음). **런타임 노드/측정값은 메모리에만** 존재 → **앱 재시작 시 휘발**(현재 한계, 잔여 작업 핵심).
- 영속 저장 현황:
  - `%APPDATA%/pulse/pulse-config.json` — 워치 폴더 경로, 백엔드 URL/API키 (Main이 보관, 렌더러 비노출)
  - `localStorage` — 다크모드, 채널 정상범위 캐시
- **DB 없음** — SQLite 미도입(잔여 작업).

### 2.4 핵심 단일소스 모듈 (이미 구현, 안정)

- `lib/backendApi.js` — 백엔드 API 계약(경로/본문/센서코드 규칙) 단일 소스
- `lib/sensorModel.js` — "열→센서" 구조 해석기(번호형/이름형/깊이형/값+온도형). 등록 채널과 ingest 매핑의 공통 소스
- `lib/classifyChannel.js`, `lib/series.js`, `lib/formatClassify.js` — 채널 분류·깊이 프로파일·포맷 판정

### 3.1 외부 런타임 의존성 — 전수 검토 결과

|---|---|---|
| **자체 백엔드 API** | HTTP(fetch) | 유일한 API. 전부 `folderService.js` → `/api/pulse/v1/*` (6.1 참조) |
| **Pretendard 폰트** | CDN(jsDelivr) | `index.html`에서 `cdn.jsdelivr.net` 로드. 오프라인 시 **시스템폰트 폴백**(동작 무관, 모양만) |

### 4.2 백엔드 연동 (부분 완료)

- **노드 등록(POST /nodes) 실전송 연결됨** — Main IPC `nodes:register`.
- **측정 전송(POST /ingest) 연결됨** — `store.syncNode`→증분 전송(워터마크 기반). 깊이 프로파일 depthLabel 전송 실측 검증.
- **★ 자동 증분 전송 동작 중** — `App.jsx`가 **60초마다 `syncAll()` 자동 호출** → 등록 노드의 원본 `.txt`에서 신규 행만 읽어 자동 전송. **"메모장에 데이터 찍히면 자동으로 백엔드 전송"은 (앱이 켜져 있는 동안) 이미 동작함.** 단, ① 앱(창)이 떠 있어야만 돌고 ② 워터마크가 메모리(재시작 시 백엔드 last_seen 기준 복원, ingest 멱등이라 안전).
- **노드 조회(GET /nodes) 연결됨** — 시작 시 백엔드 노드 목록 동기화 + 자기 파일 매칭 필터.
- 센서 생명주기 PATCH, 정상범위/운영시작일/주기 갱신 본문 구현.
- 품질 모델(ADR-0015~0018): 채널별 sensor_type·정상범위·inactive·monitoring_from·**채널 코드↔종류 일치(접두 자동)** 구현.

### 4.3 품질 인프라

- Playwright E2E **44 테스트 통과**. 렌더러(dev:web) 기준 + 순수함수 단위 테스트.
- Squirrel 인스톨러 빌드 파이프라인 동작.

> **요약**: 사용자가 보는 화면과 백엔드 전송 "통로"는 완성. **자동화 엔진·영속성·계정·알림**이 미완.

## 5. 잔여 작업 범위 🚧 (견적 대상)

> 복잡도: **S**(1~2일) · **M**(3~5일) · **L**(1~2주) · **XL**(2주+). *개략 추정이며 보정 필요.*
> 의존성: 다른 트랙(백엔드/웹)과 맞물리는 항목 표기.

| # | 작업 항목 | 내용 | 복잡도 | 의존성 |
|---|---|---|---|---|
| R1 | **로컬 영속 저장(SQLite)** | 노드/채널/측정값/큐/설정을 SQLite로 영속화. 재시작 후 복원. Main 프로세스 DB 계층 + 마이그레이션 + store 연동 | **L** | 없음(Pulse 내부) |
| R2 | **신규 파일 자동 감지** | 워치 폴더 주기 스캔으로 **새 `.txt` 파일 자동 발견**(현재는 앱 시작/수동 새로고침 때만 스캔, `usePolling`은 UI 카운트다운만). ※ 등록 노드의 신규 데이터 전송은 이미 60초 자동 동작(R4 참조) | **M** | 없음 |
| R3 | **측정값 자동 파싱 고도화** | 신규 행 파싱→센서 매핑(해석기 재사용)의 안정화. 인코딩/구분자/깨진 행 방어 강화 | **S~M** | R2 |
| R4 | **자동 전송 워커 견고화** | 60초 자동 증분 전송은 **이미 동작**(App.jsx). 보강 범위 = 워터마크 영속화(R1), 실패 재시도 상태머신, 전송 주기 설정화. (현재는 고정 60초·메모리 워터마크) | **S~M** | R1, 백엔드 |
| R15 | **백그라운드/트레이 상주 + 자동 시작** | 현재 자동 전송 타이머는 **창(렌더러)에 있어 앱을 닫으면 멈춤**. 진정한 무인 24시간 동작을 위해 시스템 트레이 상주·부팅 시 자동 실행·창 닫아도 백그라운드 유지 | **M** | 없음 |
| R5 | **오프라인 큐 + 재전송** | 미전송분 durable 큐(R1 위), 네트워크 복구 시 자동 재전송, 멱등 중복 방지 | **M** | R1, R4 |
| R6 | **로그인 시스템** | 로그인 화면 + 인증 토큰 보관(Main 보안 저장) + 세션 유지/만료 | **M** | 백엔드(계정 API) |
| R7 | **권한별 화면(RBAC)** | 관리자/일반 역할에 따른 라우팅·액션 게이팅 | **S~M** | R6, 백엔드(역할) |
| R8 | **알림 시스템** | 인앱 알림 센터 + 트리거(신규 파일/미수신/데이터 이상/전송 실패). OS 토스트 옵션 | **M** | R2,R4 / 백엔드(이상판정) |
| R9 | **차트 실데이터 연결** | 노드 상세 그래프를 mock(`mockNodeData.js`)에서 실측정/백엔드 GET으로 교체 | **S~M** | R1 / 백엔드(조회) |
| R10 | **heartbeat 연동** | `POST /heartbeat` 주기 전송(앱 생존 보고) — 계약 정의됨, 미연결 | **S** | 백엔드 |
| R11 | **자동 업데이트(옵션)** | Squirrel 자동 업데이트 피드(GitHub/사내 서버) 연결 → 수동 재설치 제거 | **S~M** | 배포 인프라 |
| R12 | **코드 서명(옵션)** | Windows 코드서명 인증서 적용(SmartScreen 경고 제거) | **S** | 인증서 구매(비용 별도) |
| R13 | **통합 테스트·안정화·실배포 검수** | E2E 확장, 실환경 장기 구동 검증, 패키징 검수 | **M~L** | 전체 |
| R14 | **폰트 로컬 번들링(옵션)** | CDN 폰트(Pretendard/JetBrains Mono)를 앱에 내장 → 외부 의존 0, 완전 오프라인 표시. recharts 등 미사용 의존성 정리 포함 | **S** | (오프라인 R5 보강) |

### 5.1 권장 단계(마일스톤) 묶음

1. **기반**: R1(영속) — 모든 자동화의 전제
2. **자동화 엔진**: R2→R3→R4 (신규파일 감지·파싱·전송 견고화) + R15(백그라운드 상주 — 앱 닫혀도 동작)
3. **안정성**: R5(오프라인)+R8(알림)
4. **계정**: R6+R7 (백엔드 계정 API 의존)
5. **마무리**: R9·R10·R13 (+옵션 R11·R12)

### 5.2 개략 합계 (보정 전 참고치)

- 필수(R1~R10, R13): 대략 **6~9주 / 1인 기준** (복잡도 합산 기반 개략치).
- 옵션(R11 자동업데이트, R12 코드서명, R14 폰트 로컬화): +**4~8일** + 코드서명 인증서 비용(외부).
- *주의: 백엔드 의존 항목(R4·R6·R7·R8·R9·R10)은 백엔드 트랙 일정과 맞물려 변동.*

## 6. 외부 연동 / 의존성

### 6.1 백엔드 API 계약 (단일 소스 `lib/backendApi.js`, 인증 `X-API-Key`)

| 메서드 · 경로 | 용도 | Pulse 상태 |
|---|---|---|
| `POST /api/pulse/v1/nodes` | 노드 등록/갱신. `{node_code, sensor_type, channels[], sensor_count, sensor_sync, report_interval_min, monitoring_from}` | ✅ 연결 |
| `POST /api/pulse/v1/ingest` | 측정 전송. `{sensorCode, measurements[{measuredAt,value,depthLabel?}], rawFile?}` | ✅ 연결 |
| `GET /api/pulse/v1/nodes`, `/{node_code}` | 노드 목록/단건 | ✅ 연결 |
| `DELETE /api/pulse/v1/nodes/{node_code}` | 삭제 | ✅ 연결 |
| `PATCH /api/pulse/v1/nodes/{node_code}` | 주기 변경 `{report_interval_min}` | ✅ 연결 |
| `PATCH /api/pulse/v1/sensors/{sensor_code}` | 생명주기 `{status: active/inactive}` | ✅ 연결 |
| `POST /api/pulse/v1/heartbeat` | 생존 보고 | 🚧 R10 |

- **센서코드 규칙**: `sensorCode = {node_code}-{channel_code}`. register는 bare code(`WL-1`), ingest는 prefix(`80053-WL-1`). 채널 코드 접두 = 그 채널 sensor_type 표준 약어(자동, ADR-0018).
- **sensor_type enum(14종)**: water_level, groundwater, pore_pressure, rainfall, inclinometer, settlement, tilt, crack, strut, vibration, strain, wind, thermo_hygro, seismic. (약어 WL/GW/PWP/RF/GI/SP/BT/CR/LC/VB/SG/WS/TH/EQ — 백엔드와 일치 확정)

### 6.2 의존성 가정 (견적 리스크)

- 백엔드 **계정/인증 API**(R6/R7)와 **이상 판정/알림 신호**(R8), **측정 조회 API**(R9)가 제공되어야 해당 Pulse 작업 완결.
- 타사 로거의 `.txt` 포맷(덮어쓰기 방식, 인코딩, 구분자)은 현재 파서가 4유형 대응. 신규 변종 포맷 출현 시 파서 확장(소규모) 추가 가능.

## 7. 제약 · 가정 · 리스크

- **플랫폼**: Windows 전용(사무실 PC). Mac/Linux 미대상.
- **단일 PC 가정**: 워치 폴더가 있는 PC 1대에서 구동. 멀티 PC 동기화는 범위 외(필요 시 별도).
- **데이터 정합성**: ingest 멱등(중복 전송 안전) 설계 — 오프라인 재전송이 안전.
- **보안**: API키는 Main 프로세스(`pulse-config.json`)에만. 코드서명/자동업데이트는 옵션.
- **테스트 한계**: 현재 E2E는 렌더러(dev:web) 기준 — Electron Main/IPC 실동작은 수동 검증. R13에서 보강 권장.

## 8. 견적 LLM을 위한 산정 가이드

- **이미 구현(4장)은 비용에서 제외**. 견적은 **5장 R1~R13** 중심.
- 항목별 **복잡도(S/M/L/XL)**와 **의존성**을 그대로 사용해 인일(person-day) 환산 → 단가 적용.
- **백엔드 의존 항목**(R4·R6·R7·R8·R9·R10)은 백엔드 견적과 **연동 버퍼**(통합/대기) 반영 권장.
- **옵션 항목**(R11 자동업데이트, R12 코드서명)은 별도 라인아이템으로 분리(R12는 외부 인증서 비용 별도).
- 권장 묶음(5.1)을 **마일스톤 단위 청구**로 제안하면 클라이언트 가시성↑.
