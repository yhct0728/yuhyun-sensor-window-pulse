# 07. Pulse 운영 동작 & 시나리오 정리

> **용도**: Pulse가 실제로 어떻게 동작하는지(현재 코드 기준, 2026-06)와 운영 방식을 시나리오로 정리한 **기술/운영 문서**.
> 견적·인수인계·운영 가이드 공통 참고. 모든 동작은 코드로 검증함(부록 코드 위치 참조).
> ⚠️ "현재 동작" = 지금 빌드에서 실제로 되는 것. "보강 예정" = 견적 문서(00) 잔여 항목.

---

## 0. 한 줄 요약 & 전제

> **"감시폴더에 모이는 센서 메모장(.txt)을, 등록해두면 60초마다 새 데이터만 자동으로 백엔드에 보낸다. 파일명이 곧 신분증이라 재부팅해도 같은 이름이면 자동 복원된다."**

- **핵심 식별자 = 파일명**(확장자 뺀 이름 = `node_code`). 데이터 정본은 **백엔드**에 저장.
- **운영 전제**: 감시 PC에서 **Pulse 창을 계속 켜둔다** + **부팅 시 자동 실행**(권장) + **파일명을 바꾸지 않는다.**

---

## 1. 무엇이 "자동"인가 (현재 코드 기준)

| 동작 | 자동? | 트리거 / 주기 | 조건 |
|---|---|---|---|
| 등록 노드의 **새 측정값 전송** | ✅ 자동 | **60초마다** `syncAll` (`App.jsx`) | 앱 켜져 있음 + 백엔드 설정됨 |
| 재부팅/재시작 후 **노드 복원·재연결** | ✅ 자동 | 앱 시작 시 `loadNodesFromBackend` | 파일명 동일 + 백엔드 설정됨 |
| 전송 실패 시 **재시도** | ✅ 자동 | 다음 60초 틱 (워터마크 유지) | 앱 켜져 있음 |
| **새 파일(새 장비) 감지** | ⚠️ 반자동 | 앱 시작 시 1회 + **수동 "새로고침"** 때만 | — |
| **앱이 닫힌 동안의 전송** | ❌ 안 됨 | (타이머가 창 안에 있음) | 앱 켜둬야 함 |

> 즉 **"메모장에 데이터 찍히면 자동 전송"은 이미 동작**한다(앱 켜둔 동안, 60초 주기). 빠진 자동화는 **① 새 파일 자동 감지 ② 앱 닫혀도 동작** 두 가지.

---

## 2. 시나리오 A — 평소 정상 운영 (앱 켜둠)

```
[상시] 감시 PC에 Pulse 창이 떠 있음
   → 로거가 .txt 에 새 측정값을 계속 기록
   → Pulse가 60초마다 등록 노드들의 새 줄을 읽어 백엔드로 자동 전송
   → 직원은 가끔 모니터링 화면만 확인 (초록=정상 수신/전송)
```
**결론**: 사람이 손댈 일 없음. 흘끔 보기만 하면 됨.

---

## 3. 시나리오 B — PC 재부팅 (파일명 동일) → 자동 복원 ✅

```
1. PC 재부팅  (윈도우 업데이트 / 정전 / 수동 재시작)
2. (자동시작 설정 시) Pulse 자동 실행
3. 앱 시작 → loadNodesFromBackend() 자동 실행
     → 백엔드 GET /nodes  (저장돼 있던 노드 전부 받음)
4. 감시폴더 스캔 → 각 파일의 이름(node_code) 추출
5. 백엔드 node_code ↔ 로컬 파일명 매칭        ← 핵심
     → 이름이 같으면 매칭 성공 → "내 노드"로 복원
6. 매칭된 노드: 원본 파일 재연결 + 센서 매핑 재계산
     + 워터마크 = 백엔드 last_seen(마지막 받은 시각)
7. 60초 타이머가 그 이후 새 데이터부터 자동 전송 재개
```

- **로컬 DB 없이도 복원됨** — 데이터 정본은 백엔드, 신분증은 파일명. (코드 주석: *"재시작 후에도 ingest 가능. 저장 불필요 — 백엔드 ingest가 완전 멱등"*)
- **중복/누락 없음** — 백엔드 ingest가 멱등이라 워터마크가 조금 겹쳐 읽어도 안전.
- **전제**: 백엔드 연결 정보(URL/키)는 `pulse-config.json`에 저장돼 재부팅 후에도 유지됨. 자동시작만 켜두면 무인 복원.

---

## 4. 시나리오 C — 파일명이 바뀌면 → 재등록 필요 ⚠️

```
파일명 변경 (예: 90030.txt → 90030_new.txt)
   → 백엔드 옛 노드(90030) ↔ 새 파일명(90030_new): 매칭 실패
   → 옛 노드: 연결될 파일 없음 → 전송 끊김 ("원본 없음" 표시)
   → 새 파일: "미등록 파일"로 뜸 → 직원이 재등록해야 함
       (백엔드에 새 이름으로 노드 새로 생성, 옛 노드는 고아 상태)
```

**운영 수칙**: **파일명을 함부로 바꾸지 말 것.** 바꿔야 하면 재등록 + (필요 시) 웹에서 옛/새 노드 연속성 재바인딩.

---

## 5. 시나리오 D — 새 장비(새 파일) 추가

```
폴더에 처음 보는 .txt 가 생김
   → 앱을 켜둔 상태라도 자동으로는 안 뜸 (현재)
   → 직원이 "새로고침" 클릭 (또는 앱 재시작)
   → "등록되지 않은 파일 N개" 표시 → 등록 마법사로 등록
   → 등록 후부터 60초 자동 전송 대상에 포함
```

- 새 파일 등장은 **새 센서/장비를 다는 가끔 있는 일**이라, 그때만 새로고침 한 번 눌러주면 됨.
- **보강 예정(R2)**: 폴더 주기 스캔으로 새 파일 자동 감지.

---

## 6. 시나리오 E — 인터넷 일시 끊김 → 자동 복구 ✅

```
[끊김] 60초 전송 시도 실패
   → 워터마크(어디까지 보냈는지) 전진 안 함 → 상태 'retry', "전송 대기 N건" 표시
   → 측정값 원본은 .txt 에 그대로 있음 (파일이 곧 버퍼)
[지속] 다음 60초 틱마다 자동 재시도
[복구] 인터넷 돌아오면 다음 틱에 성공 → 대기분 한 번에 전송, 워터마크 전진
       → 중복 없이, 누락 없이 채워짐 (ingest 멱등)
```

- **데이터 유실 없음**: 실패 시 워터마크를 안 올리므로 같은 데이터를 다음에 재시도(`store.jsx:391-393`).
- 앱이 끊김 중에 꺼져도, 재시작하면 백엔드 last_seen부터 다시 보냄 → 안전.
- **보강 예정(R5)**: 더 긴 오프라인·대량 누적을 위한 견고한 durable 큐(현재는 파일+워터마크 재시도 방식).

---

## 7. 시나리오 F — 앱(창)을 닫으면

```
Pulse 창을 X로 닫음
   → 60초 전송 타이머가 창(렌더러) 안에 있어 함께 멈춤
   → 새 측정값이 백엔드로 안 나감 (창 닫힌 동안)
   → 다시 켜면: 시나리오 B와 동일하게 복원 + last_seen 이후분 재전송
```

**그래서 "앱 계속 켜두기"가 운영 핵심.** (보강 옵션 R15 = 트레이 상주로 창 닫아도 동작)

## 8. 운영 정책 — "앱 계속 켜두기" 체크리스트

전용 감시 PC에서 무인 운영하려면 아래 4가지를 세팅:

| # | 항목 | 방법 | 분류 |
|---|---|---|---|
| 1 | **부팅 시 자동 실행** | 재부팅(업데이트·정전) 후 자동 복귀 위해 권장 | 작은 개발(권장) |
| 2 | **절전/슬립 끄기** | 윈도우 전원 옵션 "절대 절전 안 함" | PC 설정 |
| 3 | **자동 로그아웃 끄기** | 계정 로그아웃 시 앱 종료 방지 | PC 설정 |
| 4 | **창 닫지 않기 안내** | "이 창은 끄지 마세요" 직원 안내 | 운영 안내 |

> 이 4가지면 **재부팅 포함 무인 운영이 현재 구조로도 가능.** 트레이 상주(R15)는 "있으면 더 안전한 옵션".

## 9. 지금 되는 것 / 안 되는 것 (솔직 정리)

### ✅ 현재 되는 것
- 등록 노드의 새 데이터 **60초 자동 전송**
- **재부팅 후 자동 복원**(파일명 동일) — 로컬 DB 없이 백엔드+파일명으로
- 전송 실패 **자동 재시도**(데이터 유실 없음)
- 깊이 프로파일(지중경사계 등) 포함 전송

### ⚠️ 반자동 / 운영으로 커버
- **새 파일 감지** — 새로고침/재시작 시 (새 장비 추가 시에만 필요)
- **무인 24시간** — 앱 켜두기 + 자동시작 + 파일명 고정으로 커버

### 🚧 보강 예정 (견적 대상, 문서 00 참조)
- R2 새 파일 자동 감지 · R4 전송 워커 견고화(워터마크 영속·주기 설정)
- R5 견고한 오프라인 큐 · R15 트레이 상주(창 닫아도 동작)
- R1 SQLite(영속) — **재부팅 생존엔 불필요**, 오프라인 큐·로컬 이력 보강용

## 10. 핵심 원칙 — 파일명 = 신분증

- 파일명(확장자 뺀 것) = `node_code` = 백엔드 센서 식별 기준.
- **같은 이름 유지** → 재부팅·재연결 자동.
- **이름 변경** → 새 노드로 인식 → 재등록.
- 그래서 로거/폴더 설정에서 **파일명 규칙을 고정**하는 것이 운영 안정성의 핵심.
