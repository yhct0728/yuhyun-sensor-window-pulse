# 메타 프롬프트 — 3트랙 통합 견적서 생성 (금액 포함)

> **사용법**: 새 채팅을 열고 → 이 프롬프트 전체를 붙여넣고 → 아래 `[입력]` 4개 블록을 채워 함께 붙여넣는다.
> 입력 = ① 단가표 ② Pulse `00_견적용_기술총정리.md` ③ 프론트엔드 `00` ④ 백엔드 `00`.
> 산출 = **단일 통합 견적서**(트랙별 소계 + 연동 버퍼 + 총계 + 가정/리스크).

---

## [입력 1] — 단가 기준 (이 표를 채워서 함께 붙여넣으세요)

```
통화 = KRW
산정 방식 = 복잡도 등급 → 일수 → 일단가   (등급별 일수는 _SHARED_FACTS.md 척도 사용)
1일 단가 = (예: 400,000원/일)        ← 채우세요
복잡도→일수 환산(중앙값 사용):
  S = 1.5일 / M = 4일 / L = 7.5일 / XL = 15일   ← 필요 시 조정
연동 버퍼 = 트랙 간 연동이 걸린 작업마다 +0.5~1일 (조율·계약 맞춤 비용)
프로젝트 관리/QA = 개발 소계의 (예: 15%)        ← 채우거나 "없음"
부가세 = 별도 / 포함  ← 택1
```

> 단가 기준을 비우면 LLM은 금액을 산정하지 말고 **일수까지만** 내고, "단가 미입력 → 금액 보류"를 명시한다. **추측 단가 금지.**

## 역할 & 목표

당신은 유현건설 계측 모니터링 시스템 정식 계약의 **견적 총괄**이다.
3트랙(Pulse · 프론트엔드 · 백엔드)이 각자 만든 `00_견적용` 기술 문서를 받아, **모순 없는 단일 견적서**로 통합하라.

## 가장 중요한 규칙

1. **입력 문서에 적힌 사실만 사용**하라. 문서에 없는 작업을 지어내지 말 것. 문서가 "미생성"이면 그 트랙은 "**견적 불가 — 문서 대기**"로 표시하고 총계에서 제외(별도 표기).
2. **완료(✅) 항목은 견적에서 제외.** 🚧 잔여 작업만 금액 대상. 각 트랙 문서의 잔여 작업 표(ID/복잡도/의존성)를 그대로 승계하되, 중복·모순을 잡아라.
3. **경계 작업 이중 계상 금지** (가장 흔한 오류):
   - 한 작업이 두 트랙 문서에 모두 등장하면(예: "Pulse↔백엔드 ingest 연동"), **구현 비용은 한쪽에만 귀속**시키고 반대쪽은 "**연동 버퍼**"로만 계상하라.
   - 어느 쪽에 귀속했는지 표에 명시(`귀속: 백엔드 / 버퍼: Pulse`).
4. **복잡도 척도 일치 검증**: 세 트랙이 `_SHARED_FACTS.md`의 S/M/L/XL 정의를 동일하게 썼는지 확인. 어긋나면 보정하고 보고.
5. **공통 사실 정합**: sensor_type enum, `sensorCode`/`node_code` 규칙, API 경로/인증이 트랙 간 모순되면 **불일치 목록**으로 보고(임의 통일 금지 — 조율 필요로 표기).
6. **단가는 [입력 1]에 적힌 값만** 사용. 없으면 금액 보류.

## 산출물 구조 (이 순서로 출력)

### A. 통합 요약 (3줄)
- 전체 잔여 범위 한 줄, 총 일수/금액 한 줄, 가장 큰 리스크 한 줄.

### B. 트랙별 잔여 작업 표 (3개)
각 트랙마다:

| ID | 작업 항목 | 복잡도 | 일수 | 의존성 | 경계 처리 | 금액 |
|---|---|---|---|---|---|---|
| BE-R1 | … | M | 4 | 없음 | — | … |
| BE-R2 | ingest 검증 연동 | M | 4 | ★Pulse | 귀속:BE / 버퍼:Pulse(+1일) | … |

### C. 트랙별 소계
| 트랙 | 잔여 작업 수 | 개발 일수 | 연동 버퍼 | 소계 금액 |
|---|---|---|---|---|
| Pulse | … | … | … | … |
| 프론트엔드 | … | … | … | … |
| 백엔드 | … | … | … | … |

### D. 총계
- 개발 소계 합 → + PM/QA(%) → + 연동 버퍼 → 합계 → (부가세 별도/포함) → **최종 금액**.
- 환산 근거(복잡도→일수→금액)를 한 줄로 노출.

### E. 트랙 간 계약·연동 맵
- 각 트랙이 주고받는 API/데이터/인증 한눈 표. 연동 작업이 어느 트랙 일정에 막혀있는지(임계경로) 표기.

### F. 가정·리스크·불일치 보고
- 사용한 단가/환산 가정 명시.
- 트랙 문서 간 **불일치 목록**(조율 필요 항목).
- "미생성" 트랙으로 인한 **견적 공백** 명시.

---

## 완료 기준(자체 체크)

- [ ] 세 트랙 잔여 작업이 빠짐없이 표로 승계됨(완료분 제외 확인)
- [ ] 경계 작업이 한쪽에만 귀속 + 반대쪽 버퍼로만 계상(이중계상 0건)
- [ ] 복잡도 척도가 세 트랙 동일(어긋나면 보정·보고)
- [ ] 공통 사실(enum/식별규칙/API) 불일치를 임의 통일하지 않고 **보고**
- [ ] 단가는 입력값만 사용, 없으면 금액 보류 명시
- [ ] 총계 = 소계 + PM/QA + 버퍼, 부가세 처리 명시
- [ ] "미생성" 트랙은 총계에서 분리 표기

> 참고: 공통 사실 정본은 `pulse/docs/proposal/_SHARED_FACTS.md`. 트랙별 문서 생성 규칙은 `_META_PROMPT_프엔백엔.md`.
