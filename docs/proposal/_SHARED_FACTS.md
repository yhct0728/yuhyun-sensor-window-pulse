# 공통 시스템 사실 (3트랙 정합 기준 — 단일 소스)

> **이 파일이 유일한 정본이다.** Pulse·프론트엔드·백엔드 3트랙 문서와 통합 견적은 모두 이 블록을 참조한다.
> 트랙 문서가 이 파일과 다르면 → **해당 트랙의 실제 코드를 근거로** 보정하고, 불일치를 보고할 것.
> 갱신 시 이 파일만 고치고, 각 트랙은 "공통 사실은 `_SHARED_FACTS.md` 참조"로만 적는다(중복 금지).

- 최종 갱신: 2026-06-13

---

## 시스템 한 줄 그림

```
현장 로거 → [.txt 워치 폴더] → Pulse(현장 PC 수집기) → 백엔드 → 웹 프론트(모니터링)
```

## 3트랙 역할

- **Pulse**: 현장/사무실 PC 수집기(Windows 설치형 Electron 앱). 센서 측정 `.txt`를 읽어 백엔드로 전송 + 로컬 모니터링. **현장-블라인드**(노드=장비ID 단위 수집·전송, 현장 배치·안전/품질 판정은 백엔드/웹 책임). 품질 판정(이상치·결측·보정·단위변환)은 하지 않고 **raw 정직 전송 + 운영자 입력값(정상범위/생명주기/운영기준일) 전달**만.
- **백엔드**: 데이터 저장·정리·**품질판정(이상치·결측·보정)**·현장 배치·계정/인증. Pulse↔백엔드 계약 = `/api/pulse/v1/*`, 인증 헤더 `X-API-Key`.
- **웹 프론트**: 백엔드 데이터를 보여주는 모니터링 화면(현장 배치·안전 판정·경보 level1/2 표시).

## 식별 규칙 (정본)

- `node_code` = 파일명(워치 폴더의 `.txt`)
- `sensorCode` = `{node_code}-{channel}` (예: `90030-WL1`)
- 채널 코드 접두 = **해당 채널의 sensor_type 표준 약어**(아래 enum), 접미 번호는 보존. 채널 종류가 바뀌면 접두도 즉시 추종(예: `GI-1` → `GW-1`). (ADR-0018)

## 품질·생명주기 3축 (ADR-0015/0016/0017)

1. **정상범위** `valid_min/max` — 정상 센서의 raw 글리치 1개 컷. **펄스는 입력+전송만**(판정은 백엔드, 로컬 이상치 표시 X). `POST /nodes`로 전송.
2. **고장(생명주기)** — `PATCH {status:inactive}`. 평균/offline 집계에서 제외 + `excluded_sensors`.
3. **경보** level1/2 — 프론트 책임.
- **운영기준일** `monitoring_from` — 노드 단위 ISO. `POST /nodes` body. 시운전 이전 데이터는 분석 제외.
- **채널별 sensor_type** — 노드 1개에 종류 혼재 가능. `channels[]`에 sensor_type/unit, 노드 레벨은 대표/폴백.
