## [펄스 → 백엔드 요청] 잉여 센서 정리 + register 채널 동기화 옵션

### 1. 배경 (무엇이 바뀌었나)
펄스가 로거 .txt 의 패턴을 분석해 **센서 개수를 정확히 도출**하도록 고쳤습니다.
핵심 원칙: **"값 열 개수 ≠ 센서 개수"** — 패턴마다 다릅니다.

| 패턴 | 예시 헤더 | 센서 수 |
|---|---|---|
| 번호형 | `DateTime,1,2,3` | 열마다 1개 (N) |
| 이름형 | `DateTime,W-3,W-4` | 열마다 1개 (N) |
| 깊이형 | `DateTime,0.0M, … ,40.0M` | **전체 1개**(깊이는 ingest `depthLabel`) |
| 값+온도형 | `DateTime,값,온도` | **1개**(온도는 부속) |

→ 깊이형(지중경사계 등)은 이제 펄스가 `channels:[{ch:1,code:"A"}]` 1개만 보냅니다.
(이전엔 `channels` 를 안 보내서 백엔드 `inclinometer` 템플릿이 **A·B 2센서**를 자동 생성했음.)

### 2. 문제 (실측으로 확인됨)
이미 2센서로 만들어진 **기존 노드는 정리가 안 됩니다.** 현재 upsert 가 additive(추가만)라서요.

- 노드 `지중경사계_(I-4-AB)` 에 `-A`, `-B` 2센서가 남아 있음(옛 템플릿 산물).
- `POST /api/pulse/v1/nodes` 에 `channels:[{ch:1,code:"A"}]`(센서 1개) 재전송 → **201, 그러나 여전히 2개**. A 는 매칭되고 **B 는 그대로 유지됨**.
- `DELETE /api/pulse/v1/nodes/지중경사계_(I-4-AB)` → **400(거부)**. (측정데이터/배치 사유로 추정 — 펄스는 이 노드에 ingest 한 적 없음.)

### 3. 요청 (2가지)

**(A) 잉여 센서 1건 정리**
`지중경사계_(I-4-AB)` 의 **B축 센서를 제거(또는 비활성)** 해 1센서로 맞춰 주세요.
대안: 이 노드를 **force 삭제**해 주시면 펄스가 1센서로 재등록하겠습니다(지금은 DELETE 가 400 이라 펄스 쪽 정리가 불가).

**(B) register 채널 동기화 옵션 추가**
`POST /api/pulse/v1/nodes` 요청 본문에 보낸 `channels` 에 **없는 기존 센서**를 어떻게 할지 옵션화해 주세요.
- 기본값: 지금처럼 **유지(additive)** — 기존 동작 호환.
- 신규 모드: 펄스가 "이 노드의 센서 집합은 이 channels 가 전부"라고 선언 → 빠진 센서 **비활성(또는 삭제)**.
  - 제안 형태: 본문에 `"sensor_sync": "replace"`(없으면 `"append"` 기본). 필드명/값은 백엔드 재량.
- 목적: 앞으로 파일 구조가 바뀌어 센서가 줄어드는 경우(열 삭제, 깊이형 오등록 정정)에 펄스가 스스로 정합을 맞출 수 있게.

### 4. 수용 기준 (이렇게 되면 완료)
1. `지중경사계_(I-4-AB)` 조회 시 센서가 **1개**(A 또는 단일 프로파일)로 정리됨.
2. `sensor_sync:"replace"` 로 `channels:[A]` 재전송 시 → B 가 비활성/삭제되고 활성 센서 **1개**.
3. `sensor_sync` 없이 보내면 → 기존대로 additive(회귀 없음).
4. 변경된 동작을 한 줄로 회신해 주시면(필드명/값/적용 엔드포인트) 펄스가 `nodeRegisterBody` 에 즉시 반영하겠습니다.

### 5. 참고 (기존 합의 — 이미 구현됨)
- `channels` 오면 채널당 센서 1개 생성, 센서코드 = `{node_code}-{code}`.
- ingest 의 `sensorCode` 도 `{node_code}-{code}`(register 는 bare code, ingest 만 prefix).
- 멱등 additive upsert(현재). → 위 (B) 가 이 동작에 옵션을 더하는 요청입니다.

### 6. 펄스 측 현황
- 센서 수 도출은 `lib/sensorModel.js`(`resolveSensors`)에서 끝. **펄스가 더 할 건 없습니다.**
- 위 2건은 **백엔드 정책/데이터 정리** 사안입니다. 답 주시면 1줄 반영하겠습니다.
