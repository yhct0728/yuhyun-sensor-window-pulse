# 백엔드 전달용 프롬프트 — GET 노드 응답에 "마지막 수신 시각(last_seen)" 추가

> 아래 블록을 그대로 복사해 백엔드에 전달하세요.

---

## [펄스 → 백엔드 요청] GET /nodes 응답에 `last_seen`(마지막 측정 시각) 추가

### 배경
펄스는 노드의 **수신중 / 지연 / 끊김**을 "**마지막으로 데이터 받은 시각** vs 지금"으로 판정합니다
(수신 주기 ×1.5 이내=수신중, ×3 이내=지연, 초과/모름=끊김).

### 문제 (실측)
`GET /api/pulse/v1/nodes/{code}` 응답에 **마지막 수신 시각 필드가 없습니다.**
- 80053 응답: `last_seen` / `last_data_at` **모두 없음(undefined)** (있는 건 `updated_at`=노드 레코드 수정시각, 데이터 시각 아님).
- 그래서 펄스는 "마지막 수신 시각 = 모름" → **끊김으로 표시**.
- 실제로는 데이터 정상: 파일 마지막 행 `2026-06-01 00:00`, ingest 도 `201 OK (393건)`. **끊긴 게 아닌데 끊김으로 뜸.**

### 부작용 (같은 원인)
마지막 수신 시각이 없으니 펄스가 증분 기준점(워터마크)을 못 잡아 **매 폴링마다 전체(393건)를 재전송**합니다(멱등이라 사고는 없지만 낭비).

### 요청
`GET /api/pulse/v1/nodes` 와 `/nodes/{code}` 응답의 **각 노드에 마지막 측정 시각**을 넣어 주세요.
- 필드명: **`last_seen`** (ISO8601, 예 `"2026-06-01T00:00:00"`). `last_data_at` 등 다른 이름이면 알려주세요 — 펄스가 그 키를 읽겠습니다.
- 의미: 그 노드(센서)로 **마지막으로 ingest 된 측정값의 measuredAt** (없으면 `null`).
- 노드 단위 1개면 충분(센서별까지는 불필요). 여러 센서면 그중 가장 최신.

### 수용 기준
1. GET 응답에 `last_seen` 이 있고, ingest 후 그 노드의 최신 measuredAt 으로 갱신됨.
2. 데이터 없는 노드는 `last_seen: null`.
3. 펄스가 이 값으로 수신중/지연/끊김을 정확히 판정 → 오늘 데이터 들어온 80053 은 "수신중"으로 표시됨.

### 참고
- 펄스 정규화(`normalizeBackendNode`)는 이미 `last_seen / lastSeen / last_data_at / lastDataAt` 을 읽도록 돼 있어, 이 중 아무 키로 주셔도 즉시 반영됩니다(추가 펄스 작업 없음).
- 이 값은 ingest 의 워터마크(증분 전송 기준)로도 쓰여, 중복 재전송도 사라집니다.
