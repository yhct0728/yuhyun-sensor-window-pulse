# 0008. 계측기 종류 마스터 + 종류 레벨 공식 + 센서 offset/scale (0006·0007 대체)

- 상태: 채택됨 — 단 **공식/보정 부분은 [ADR-0009](0009-pulse-원본전달-공식보정-제거.md) 로 대체**됨 (계측기 종류 마스터·readOnly 패턴은 유지). (ADR-0006, ADR-0007 을 대체함)
- 날짜: 2026-05-26
- 결정자: 사용자 / Claude Code
- 관련: `lib/sensorTypes.js`, `lib/formulaEngine.js`, `lib/permissions.js`, `lib/calibration.js`(재작성), `pages/SensorTypes.jsx`, `components/sensor-types/*`, `components/node-detail/CalibrationModal.jsx`, `App.jsx`

## 맥락

보정을 노드 등록 모달의 "보정값"까지만 만든 상태였다. 이제 전체 구조로 확장:
**계측기 종류 마스터 관리 + 종류별 공식 + 센서별 보정**. 향후 백엔드가 단일 출처(SSOT)가 되어 Pulse 는 v2 에서 read-only 로 전환될 예정이라, "지금은 편집 가능, 나중에 한 줄로 read-only 전환"이 가능한 구조가 요구됐다.

사용자 확정: **"계측 종류마다 공식은 다르지만, 같은 종류 안에서는 숫자(영점/배율)만 다르다"**(방법 A). → 공식을 종류 레벨에 둔다. 이는 ADR-0007("공식을 노드/채널별로")을 뒤집는 결정이다.

## 결정

- **공식 = 계측기 종류 레벨** (`Formula {expression, constants, version, updated_at}`), mathjs 로 평가. 센서별 차이는 **offset/scale** 보정으로.
- 데이터 흐름: **raw → 종류 공식(formulaEngine) → 센서 보정(offset/scale) → 표시값**.
- 신규 라이브러리:
  - `sensorTypes.js` — 22종 시드 + 카테고리 5 + 로컬 스토어(`pulse:sensorTypes`)
  - `formulaEngine.js` — `applyFormula`/`validateFormula` (eval 금지, mathjs evaluate, scope=raw+constants)
  - `permissions.js` — `FORMULA_EDITING_ENABLED` 전역 토글(한 곳)
  - `calibration.js` 재작성 — 센서 offset/scale + 종류 공식 합성, `pulse:sensorCalibrations` 스토어
- 신규 화면: `SensorTypes` 페이지(카테고리 탭 + 카드 그리드 + 우측 슬라이드 상세[기본정보/공식설정/사용센서] + 공식 미리보기). 사이드바 "계측기 종류"(`sensors`) 라우팅 활성.
- `CalibrationModal` 재작성: 채널별 **offset/scale**(종류 공식은 읽기 전용 표시), 영점·일괄·라이브.
- **readOnly 패턴**: 모든 공식/보정 UI 가 `readOnly` prop 지원 + `ui/ReadOnlyBanner`. `permissions` 한 곳만 바꾸면 전체 전환.
- 시스템 22종은 코드/이름 수정 보호(`is_system`), 사용자 종류는 추가/삭제 가능.

## 결과

- 좋은 점: 종류 마스터·공식·보정이 백엔드 API 형식으로 설계돼 Phase 4 이전이 쉬움. readOnly 한 줄 전환 준비 완료. 변환 로직이 `formulaEngine` 한 곳에 집중.
- **0006/0007 대체**: 채널별 선형/다항 템플릿 → 종류 expression 공식 + 센서 offset/scale 로 일원화.
- 트레이드오프:
  - 종류 레벨 공식은 **같은 종류 내 공식 "모양" 차이를 못 담음**(사용자 확정상 숫자만 다르므로 무방).
  - **사용 센서 탭은 placeholder** — 등록 노드(sites)가 대시보드 로컬 상태라 미연동(추후 공유 상태로 올린 뒤 연결).
  - **localStorage 사용**: 프로젝트 규칙(다크모드 외 금지)을 이 건에 한해 명시적으로 허용(스펙 지시). Phase 2 SQLite 로 마이그레이션 예정.
  - 보정값 영속은 노드 id 기준 best-effort(노드 등록이 메모리라 세션 한정).
- 검증: 공식엔진+합성 단위 15/15, E2E `sensor-types.spec` 7/7(+기존 14 = 21/21), readOnly 모드 캡처(배너·disabled·버튼숨김·미리보기 동작), 콘솔 에러 0.

## 대안

- **ADR-0007 유지(공식 노드/채널별)** — 같은 종류 내 모양 차이까지 담지만, 사용자 도메인(같은 종류=숫자만 차이)엔 과하고 백엔드 SSOT 모델과 안 맞음. 기각.
- **자유 eval** — 보안 위험. mathjs 제한 평가로.
