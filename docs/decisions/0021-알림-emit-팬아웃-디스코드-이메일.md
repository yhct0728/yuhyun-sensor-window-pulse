# 0021. 외부 알림은 emit() 한 곳에서 디스코드·이메일로 팬아웃한다

- 상태: 채택됨
- 날짜: 2026-08-22
- 결정자: 사용자 / Claude Code
- 관련: 백엔드 `src/notifications/outbound.service.ts`, `daily-report.service.ts`

## 맥락

사용자 요구: **"매일 휴대폰 메시지나 여러 방법으로 송신해서 보고하고 싶다."** 채널은 **디스코드 + 이메일 둘 다**로 정했다.

핵심 갈림길은 **누가 보내느냐**였다.

- **Pulse(PC 앱)가 직접** — 지금 바로 만들 수 있지만 **PC 가 꺼지면 아무 메시지도 안 온다.** 그런데 PC 가 꺼진 상황이야말로 제일 알아야 할 상황이다. "조용함"이 정상인지 사고인지 구분되지 않는다.
- **서버(GeoMonitor)가** — Pulse 는 생존 신호만 보내고 서버가 침묵을 감지해 대신 알린다.

후자를 골랐다. 조사해보니 백엔드에 이미 필요한 것이 대부분 있었다: heartbeat 엔드포인트, `PulseMonitorService`(수집기 오프라인 감지), `NodeMonitorService`(노드 오프라인·고장 의심), 인앱 알림(DB + SSE), `MailService`(SMTP). **빠진 것은 외부 채널 발송과 일일 요약뿐이었다.**

## 결정

**`NotificationsService.emit()` 한 곳에 외부 발송을 붙인다.**

모든 알림은 이미 `emit()` 을 거친다. 여기에 팬아웃을 달면 **지금 있는 알림과 앞으로 추가될 알림이 자동으로 외부까지 나간다** — 알림 종류마다 발송 코드를 새로 쓰지 않는다.

1. `OutboundService.deliver()` — 디스코드 웹훅 + 이메일. `emit()` 이 DB 저장·SSE push 를 끝낸 뒤 호출.
2. **절대 throw 하지 않는다.** 알림 발송 실패가 원 작업(노드 상태 전이 등)을 깨면 안 된다.
3. 채널이 미설정이면 **그 채널만 조용히 건너뛴다.**
4. **수신자가 0명이어도 외부로는 보낸다** — 담당자 계정이 없다고 사고를 놓치면 안 된다.
5. `DailyReportService` — 매일 정해진 시각(KST, 기본 8시)에 요약 1건. **문제가 없어도 보낸다.**
6. Pulse 는 60초마다 heartbeat 를 보낸다(서버 판정 기준 3분보다 짧게).

### 조용해도 매일 보내는 이유

"문제 있을 때만 보내기"는 **알림 체계 자체가 고장나면 영원히 조용해지고, 그 침묵을 알아챌 방법이 없다.** 매일 오는 요약은 내용보다 **"이 감시 체계가 살아있다"는 증명** 역할이 크다.

### 채널 역할 분담

- **디스코드** — 속보. 폰 알림이 바로 오고 표·색을 쓸 수 있다. 웹훅 주소 하나면 끝.
- **이메일** — 기록 보관. 나중에 찾아볼 수 있고 상부 보고에도 쓴다.

카카오 알림톡은 더 확실하지만 사업자 등록·채널 개설·템플릿 사전 심사(1~2주)가 필요해 후순위로 미뤘다.

## 결과

**좋은 점**

- 붙인 곳이 한 군데라 알림이 늘어도 발송 코드가 안 늘어난다.
- 기존 감지 로직(수집기 오프라인·노드 오프라인·고장 의심)을 전혀 안 건드리고 외부 알림이 붙었다.
- PC 가 죽어도 서버가 알린다 — Pulse 직접 발송으로는 불가능한 부분.
- 두 채널 모두 무료·즉시 구축.

**트레이드오프**

- 모든 알림이 외부로 나간다. 알림 종류가 늘면 시끄러워질 수 있다 — 그때 type 별 필터가 필요하다.
- 디스코드 웹훅 주소를 아는 사람은 누구나 그 채널에 글을 쓸 수 있다. 환경변수로만 두고 저장소에 넣지 않는다.
- 발송 실패는 로그만 남고 재시도하지 않는다. 일일 요약이 그 공백을 메운다.

**필요 설정 (환경변수)**

| 키 | 뜻 |
|---|---|
| `DISCORD_WEBHOOK_URL` | 디스코드 채널 웹훅 주소 |
| `REPORT_EMAIL_TO` | 받는 사람(쉼표로 여러 명) |
| `SMTP_HOST/PORT/USER/PASS`, `MAIL_FROM` | 메일 계정 (기존 MailService 와 동일) |
| `DAILY_REPORT_HOUR` | 요약 발송 시각(0~23, KST). 기본 8 |
| `DAILY_REPORT_ENABLED` | `false` 면 끔 |

**점검 방법**

- `GET /api/app/v1/notifications/outbound/config` — 어느 채널이 연결됐는지
- `POST /api/app/v1/notifications/outbound/test` — 샘플 1건 발송
- `POST /api/app/v1/notifications/daily-report/run` — 일일 요약 즉시 발송

## 대안

- **Pulse 가 직접 발송.** 백엔드를 안 건드려도 되지만 PC 가 꺼지면 침묵한다. 가장 중요한 사고를 놓친다.
- **알림 종류마다 발송 코드 작성.** 종류별로 문구를 다듬을 수 있지만, 새 알림을 추가할 때마다 빠뜨리기 쉽다.
- **카카오 알림톡 우선.** 국내에서 가장 확실하지만 심사에 1~2주. 나중에 채널 하나 더 추가하는 형태로 붙일 수 있다.
