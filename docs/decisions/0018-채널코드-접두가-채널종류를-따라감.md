# 0018. 채널 코드 접두 약어 = 그 채널의 sensor_type 표준 약어

## 맥락

[ADR-0017](0017-채널별-sensor-type-노드내-종류혼재.md)로 **채널별 `sensor_type`** 은 보냈지만, 채널 **코드**는 여전히 노드 대표 종류 하나의 접두로 생성됐다(`resolveSensors` 의 `prefix = sensorChannelCode(sensorType)` — 노드 레벨). 그래서 한 노드에 종류가 섞이면 **코드 약어와 종류가 어긋났다.**

실사례 `node 90030`(시추공): 1번 채널이 실제 지하수위계인데 노드 대표(지중경사계 GI)에 휩쓸려 `90030-GI-1` 로 등록됨(나머지 `GI-2~21` 은 지중경사계로 정상).

이게 위험한 이유: **백엔드 ingest 는 `sensorCode` 로만 센서를 찾는다**(측정 payload 에 종류 없음). 백엔드가 코드를 `GW-1` 로 바로잡아도 펄스가 계속 `GI-1` 로 보내면 **매칭 실패 → 데이터 버려짐.** 따라서 등록·측정 양쪽에서 펄스가 올바른 약어를 보내야 한다.

약어표(14종)는 백엔드와 대조한 결과 **펄스의 기존 `SENSOR_TYPES.ch` 와 전부 일치**했다(SP/BT/LC/EQ 등 펄스 약어를 백엔드가 표준으로 채택). → **약어표 자체는 펄스 수정 불필요.** 남은 건 "코드를 어느 종류에서 뽑느냐"였다.

## 결정

**채널 코드 접두를 노드 대표 종류가 아니라 "그 채널 자신의 sensor_type"에서 뽑는다. 접미 번호(seq=파일 내 위치/심도)는 보존한다.**

- `resolveSensors(analysis, { …, channelTypes })` 에 채널 종류 override 맵(키=`seq`, 1-based) 추가. 채널별 종류 결정 순서: **명시 override > 헤더 코드 추론(`guessSensorTypeFromCode`) > 노드 대표(폴백).** 코드 = `{sensorChannelCode(chType)}-{seq}`. 각 센서에 해석된 `sensorType`/`seq` 부착.
- 위저드 `chTypes` 를 **불안정한 코드 키 → 안정적인 `seq` 키**로 변경하고 `channelTypes` 로 전달 → 채널 종류를 바꾸면 코드가 즉시 따라 바뀜(`GI-1 → GW-1`). 등록 본문 `channels[]` 는 같은 센서 객체의 `code`+`sensorType` 를 그대로 실어 **코드 약어와 종류가 구조적으로 항상 일치.**
- 등록 코드 == 측정 코드: 이미 단일 소스(`sensors[].code`)를 등록·ingest 가 공유하므로 자동 보장. 재접속 시엔 백엔드 센서코드를 위치로 덮어쓰므로(`store.jsx`) 백엔드가 정본.

## 결과

- 좋은 점: 한 노드에 종류가 섞여도 코드↔종류 불일치 구조적으로 차단. 헤더가 종류를 암시하면(`GW-1`/`GI-2`) 노드 대표가 다른 채널을 덮지 않음.
- 검증: E2E 44/44(단위 5 — override·접미보존·sensorType부착·회귀·헤더추론, UI 끝단 1 — 노드=지중경사계+채널1=지하수위계 → `GW-1`/groundwater/m).
- 범위 제외(의도): **노드 상세 드로어에서 기존 노드의 종류 변경 → 코드 리네임은 하지 않음** — 이미 등록된 노드의 코드는 백엔드가 정본이라 리네임 = 백엔드 동시 정정 필요(아래 후속).
- 깊이형(프로파일) 단일 센서 코드는 여전히 축문자(`defaultDepthCode` A/P) — 약어 통일 여부는 별도 합의 대상.

### 후속(코드 외 — 조율 필요, 단독 선반영 금지)

- `90030` 전환: 펄스가 1번 채널을 지하수위계로 재등록(→ `GW-1`)하는 **타이밍에** 백엔드가 DB `90030-GI-1 → 90030-GW-1` 리네임(내부 id 유지로 과거 데이터 보존). ⚠️ 펄스 `sensor_sync:'replace'` 가 사라진 `GI-1` 을 정리하려 들어 리네임과 경합 가능 → **순서(백엔드 리네임 先 → 펄스 GW 송신) 합의 후 진행.**

## 대안

- **약어표를 바꾼다**: 백엔드가 펄스 약어를 표준 채택해 불필요.
- **접두를 노드 종류로 유지(ADR-0017 상태)**: 90030 류 코드↔종류 불일치 재발 — 기각.
- **드로어에서도 즉시 코드 리네임**: 등록된 노드 코드는 백엔드 정본 → 단독 리네임은 매칭 깨짐 위험. 동시 정정으로 처리.
