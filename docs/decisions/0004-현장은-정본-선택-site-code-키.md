# 0004. 현장을 Pulse 에서 생성하지 않고 정본 목록에서 선택 (site_code 키)

- 상태: 채택됨
- 날짜: 2026-05-25
- 결정자: 사용자 / Claude Code
- 관련: `src/lib/mockData.js`(SITE_CATALOG), `src/pages/Dashboard.jsx`, `RegisterNodeModal.jsx`, `BulkRegisterModal.jsx`

## 맥락

노드 등록 시 현장을 "+ 새 현장 추가"로 즉석 생성하던 방식은, 현장이 **자동으로 조용히 생기면서** location 이 하드코딩(`'등록한 현장'`)되고 이름 오타로 중복 현장이 생길 위험이 있었다. 또한 매칭 키가 **현장 이름(`s.name`)** 이라 재명명·중복에 취약했다.

결정적으로: **Pulse 의 목적은 "데이터가 제때 잘 수신되는가"를 모니터링하는 것**이고, **현장 관리(생성/수정/도면/센서 배치)는 이미 웹앱이 정본으로 보유**한다. 정본 현장 스키마(`site_code`, `name`, `location`, `has_floor_plan`, `sensor_positions`, `latitude/longitude`, `managers`)를 보면 대부분 웹의 시각적 관리 기능용이다.

## 결정

- Pulse 는 현장을 **생성/관리하지 않는다. 정본 목록에서 "선택"만** 한다.
- 등록 모달의 현장 입력을 **드롭다운(정본 목록) 선택**으로 바꾸고, "+ 새 현장 추가"(인라인 생성)는 제거했다.
- 현장 연결 키를 **`name` → `site_code`** 로 교체. 노드에 `siteCode` 를 저장하고, `registerNodes` 는 `site_code` 로 현장을 찾는다.
- 정본의 **부분집합만** 사용: `id`, `siteCode`, `name`, `location`(+`description`). 도면/센서배치/위경도/담당자는 제외(모니터링 불필요, 웹 몫).
- 현재는 `mockData.SITE_CATALOG` 에 정본 2건을 시드. 추후 `window.electronAPI.getSites()` 로 교체.
- **현장 상세 / 현장 관리 페이지는 만들지 않는다(보류).** 사이드바 stub 유지.

## 결과

- 좋은 점: 유령 현장·중복·하드코딩 location 문제 해소. 정본과 키(`site_code`)가 일치해 향후 백엔드 동기화가 단순. 범위가 "수신 모니터링"이라는 본 목적에 집중됨.
- 트레이드오프: Pulse 단독으로는 새 현장을 만들 수 없다(의도된 제약 — 생성은 웹앱). 시드가 비면 등록 불가하므로 `getSites` 연결 전까지는 시드에 의존.
- 후속: 정본 `sensor_positions` 라벨(`WL-01` 등)이 .txt 노드명과 대응 → 추후 **현장↔노드 자동 매칭**으로 수동 선택을 대체할 수 있게 가볍게 설계함.

## 대안

- **인라인 생성 유지(동시 생성)** — 마찰은 적지만 정본과 어긋나는 유령 현장 양산. 기각.
- **현장 선등록 필수** — 계층은 명확하나 "파일 모니터링" 도구엔 과한 의식이고 빈 현장을 양산. 기각.
