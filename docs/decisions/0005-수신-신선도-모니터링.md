# 0005. 수신 신선도(정상/지연/끊김)를 파일 mtime + 예상 주기로 판정

- 상태: 채택됨
- 날짜: 2026-05-25
- 결정자: 사용자 / Claude Code
- 관련: `src/lib/reception.js`, `Dashboard.jsx`, `NodeRow/SiteCard/SiteCardGrid/CompactList/MetricCards/Header`, [ADR-0004](0004-현장은-정본-선택-site-code-키.md)

## 맥락

Pulse 의 본 목적은 **"데이터가 제때 잘 수신되는가"** 다(ADR-0004). 실제 값 파싱(Phase 3) 전이라 currentValue 는 더미(0)이므로, **지금 유의미한 신호는 값 이상치가 아니라 "수신 신선도"** 다. 그러나 대시보드는 값-상태(ok/warn/danger)만 표시하고 있었고, 등록된 노드에 실제 수신 시각이 없었다.

## 결정

- 노드에 **`lastReceived` = 원본 .txt 의 mtime**(등록 시 `file.lastModified`)을 저장한다.
- `src/lib/reception.js` 로 신선도를 판정한다 (`now` 기준 스냅샷):
  - 정상(ontime): 경과 ≤ 주기 × **1.5**
  - 지연(late): 1.5× < 경과 ≤ **3×**
  - 끊김(stale): 경과 > 3×  ← 미수신
  - 대기(unknown): `lastReceived` 없음
- 대시보드를 수신 상태로 구동:
  - **NodeRow / CompactList**: 점·틴트·경과 라벨("5분 전" / "3시간째 없음")을 reception 으로.
  - **SiteCard / SiteCardGrid**: 현장 강조·제목 배지·푸터(정상/지연/끊김)·"마지막 수신"을 reception worst/counts 로.
  - **MetricCards**: 값(정상/의심값/오류) → **수신(정상 수신/지연/끊김)** 으로 재해석(매핑은 Dashboard 에서).
  - **Header**: 끊김/지연 있을 때 경보 칩("N개 미수신" / "N개 수신 지연").
- **새로고침 = 재수신 반영**: 재스캔된 파일 mtime 으로 등록 노드의 `lastReceived` 를 갱신.

## 결과

- 좋은 점: 목적(수신 감시)이 대시보드 헤드라인으로 드러난다. 폴링 워커(Phase 3) 도입 시 `lastReceived` 갱신원만 폴링 결과로 바꾸면 그대로 동작.
- 트레이드오프:
  - **테이블 뷰(DataTable)는 아직 값-상태 표시 — reception 미반영(후속 작업).**
  - 폴링 워커 전이라 `now` 기준 스냅샷이며, 등록 노드의 수신 시각은 새로고침/재스캔 때만 갱신된다.
  - 메트릭 카드 의미를 수신으로 바꿨으므로, 실제 값 이상치(Phase 3)가 생기면 두 차원을 분리 표기해야 한다.
- 단위 검증: 경계 케이스 8/8 통과, 브라우저 렌더(라이트/다크) 콘솔 에러 0.

## 대안

- **값-상태에 끼워 넣기**(reception→status 덮어쓰기) — 두 차원이 섞여 Phase 3 에서 충돌. 별도 차원으로 분리.
- **폴링 워커부터 구현** — 백엔드/워커는 후순위(프론트 우선 목표). mtime 스냅샷으로 먼저 가치 구현.
