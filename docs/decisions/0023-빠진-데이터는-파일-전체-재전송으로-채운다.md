# 0023. 빠진 데이터는 파일 전체 재전송으로 채운다 (원본 .txt 는 건드리지 않는다)

- 상태: 채택됨
- 날짜: 2026-10-14
- 결정자: 사용자 / Claude Code
- 관련: `src/lib/store.jsx`(`syncNode`), `src/components/nodes/NodeDetailDrawer.jsx`, `src/folderService.js`(`ingestToBackend`), `tests/resend-all.spec.js`, CHANGELOG `[Unreleased]`

## 맥락

펄스는 **마지막 전송 시각(워터마크) 뒤의 행만** 보낸다. 앱을 다시 켜면 워터마크는 서버가 마지막으로 받은 시각이 된다.

그래서 워터마크보다 **앞선 시각이 서버에 빠져 있으면 다시 보낼 방법이 없었다.** 현장에서는 "메모장(.txt)을 고치면 다시 올라가느냐"는 질문이 나왔다. 올라가지 않는다. 펄스는 파일이 바뀌었는지가 아니라 각 줄의 시각만 본다.

남은 방법은 노드 삭제 후 재등록뿐이었는데, 삭제하면 그 노드의 서버 데이터가 지워진다.

## 결정

노드 상세 → 전송 큐 탭에 **"처음부터 다시 보내기"** 버튼을 둔다. 누르면 워터마크를 무시하고 **파일 전체를 한 번** 보낸다.

- 서버 ingest 는 같은 (센서, 시각)을 무시한다(`ON CONFLICT DO NOTHING`). 그래서 **서버에 없는 시각만 채워지고 이미 있는 값은 바뀌지 않는다.**
- 서버는 옛 시각 묶음으로 센서의 현재 상태를 덮지 않는다(백엔드 `ingest.service.ts` 확인).
- 결과를 숫자로 알려 준다: 보낸 행 수 + 서버가 새로 저장한 건수(ingest 응답의 `inserted`).
- 실패하면 평소 전송 상태(버퍼·워터마크)는 건드리지 않는다. 다시 누르면 된다.
- 원본 .txt 는 계속 읽기 전용이다. 값 수정은 서버 관리자 화면(측정값 수정)에서 한다.

## 결과

**좋은 점**

- 메모장을 건드리거나 노드를 지우지 않고 빈 곳을 채운다.
- 몇 번을 눌러도 결과가 같다(멱등).

**감수하는 점**

- 파일에 남아 있지 않은 행은 못 채운다(로거가 덮어써 사라진 구간).
- 서버에 그 시각이 **빈 값(결측)으로 이미 있으면** 다시 보내도 안 바뀐다. 이건 측정값 수정 화면에서 넣어야 한다.
- 파일 전체를 센서마다 요청 하나로 보낸다(최초 등록 때의 백필과 같은 경로). 아주 큰 파일은 오래 걸리거나 실패할 수 있다.
- 늦게 채워진 값의 통계 품질 판정은 그 시점이 아니라 최신 값 기준으로 이뤄진다(백엔드 동작).

## 대안

- **메모장(.txt)을 고쳐 다시 올리기** — 기각. 시각이 워터마크 앞이면 어차피 건너뛴다. 원본은 읽기 전용 원칙이다.
- **노드 삭제 후 재등록** — 기각. 서버 데이터가 지워지고 파일에 남은 것만 돌아온다.
- **서버와 비교해 빈 구간만 골라 보내기** — 보류. 서버에 "어느 시각이 있나"를 묻는 API 가 새로 필요하다. 전체 재전송이 멱등이라 지금은 필요 없다.
- **기간을 골라 다시 보내기** — 보류. 화면이 늘어난다. 전체를 보내도 결과가 같다.
