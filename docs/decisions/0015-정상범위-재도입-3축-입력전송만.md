# 0015. 정상범위(valid_min/max) 재도입 — 3축 모델, 펄스는 입력+전송만(판정=백엔드)

- 상태: 채택됨
- 날짜: 2026-06-05
- 결정자: (센서 백엔드 스펙 / 사용자 / Claude Code)
- 관련: [ADR-0014](0014-정상범위-폐기-고장-임계값-두-축.md)(valid_min/max 제거 부분을 대체), [ADR-0013](0013-이상치-유효범위-펄스-판정.md), [ADR-0010](0010-현장-블라인드-노드-수신-중심-v2.md), `src/lib/backendApi.js`(`nodeRangeBody`), `src/lib/store.jsx`(`saveChannelRanges`), `src/components/nodes/NodeDetailDrawer.jsx`, CHANGELOG `[Unreleased]`

## 맥락

ADR-0014 는 백엔드가 valid_min/max 계약을 되돌렸다는 판단으로 펄스에서 정상범위를 **전면 제거**했다(고장 dead + 임계값 level 두 축). 그런데 센서 백엔드가 같은 날 스펙을 다시 정리해, 품질을 **세 가지로 명확히 구분**하면서 valid_min/max 를 **다시 보내달라**고 요청했다:

1. **정상범위(valid_min/max)** — *정상* 센서가 가끔 뱉는 "튄 값(raw 0 등 글리치)" **1개**를 버림. 백엔드가 범위 밖 raw 를 자동 invalid 처리(평균·상태·알람에서 제외).
2. **고장(dead)** — 센서가 *통째로* 고장. `PATCH /sensors/{code} {status:"dead"}` → 노드 평균·offline 제외.
3. **경보 임계(level1/2)** — *진짜 위험값* 알람. 프론트/운영자 설정, 펄스 무관.

핵심 차이: ADR-0013 은 valid_min/max 를 펄스가 **로컬에서 직접 이상치 판정·표시**까지 했는데, 이는 "판정=백엔드" 원칙(ADR-0010)과 충돌했다. 새 스펙은 판정을 **백엔드 단독**으로 명시한다.

## 결정

valid_min/max 를 **재도입하되, 펄스는 입력·전송만 한다(판정은 백엔드).**

- **입력**: 노드 상세 드로어 "정상 범위" 섹션에서 센서(채널)별 raw 하한/상한 입력. 행 표시는 **'설정됨 / 검사 안 함'** 뿐 — 로컬 이상치/정상 판정 표식은 두지 않는다.
- **전송**: "정상범위 저장" 버튼 → 별도 API 없이 **노드 등록(`POST /api/pulse/v1/nodes`)을 같은 `node_code` 로 재전송**해 기존 센서의 `valid_min`/`valid_max`(raw 기준)를 갱신(sticky). 화면값 그대로(WYSIWYG, 미입력=null=해제). 최소 본문 `{node_code, sensor_type, channels:[{code, valid_min, valid_max}]}` — **`sensor_sync`/`name`/`sensor_count` 미포함**(additive 기본, 다른 센서 무영향). `spike` 는 백엔드가 무시하므로 안 보냄.
- **판정 안 함**: `lib/outlier.js`·이상치 배지는 **복원하지 않는다.** 범위 밖 판정·invalid 처리는 백엔드 전담(ADR-0010 원칙 유지). 펄스는 정직한 raw 를 그대로 전송.
- **보수적 입력 가이드**: UI 도움말에 "물리적으로 불가능한 raw 만 보수적으로 — 너무 좁히면 실측까지 무효"·"과거 데이터엔 소급 안 됨"을 명시(백엔드 스펙 주의사항 반영).
- 입력값 임시 영속: `localStorage pulse:channelRanges`(Phase 2 SQLite). `rangeKey` 는 `lib/store.jsx` 로컬 헬퍼(outlier.js 부활 없음).

## 결과

- 좋은 점: 세 축(글리치 컷 / 고장 / 경보)이 명확히 분리되고 책임 경계가 또렷함 — 펄스=입력+raw 전송, 백엔드=invalid 판정·평균, 프론트=경보. ADR-0013 이 어겼던 "판정=백엔드" 원칙을 지키면서 기능만 되살림.
- 검증: 렌더러 빌드 0 에러, E2E 30/30 통과(정상범위 단위 2 + UI 설정됨/검사안함 1 + 저장 흐름 1 추가, 이상치 판정 테스트는 미부활).
- 트레이드오프: 수집 단계에서 범위 이탈을 즉시 눈으로 보던 보조 표시는 없음 — 대신 백엔드 invalid 처리에 의존(설계상 의도).

## 대안

- **ADR-0014 유지(완전 제거)**: 백엔드가 valid_min/max 를 다시 요구 — 불가.
- **ADR-0013 그대로 부활(로컬 이상치 표시 포함)**: "판정=백엔드" 원칙과 중복·충돌 — 기각(입력+전송만 채택).
