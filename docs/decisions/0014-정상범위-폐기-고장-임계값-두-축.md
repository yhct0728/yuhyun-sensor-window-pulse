# 0014. 정상범위(valid_min/max) 폐기 — 고장(dead) + 임계값(level) 두 축으로 단순화

- 상태: **일부 대체됨 — valid_min/max 제거는 [ADR-0015](0015-정상범위-재도입-3축-입력전송만.md)로 뒤집힘(2026-06-05). dead/level 두 축 정의는 유효(0015의 3축 모델로 흡수).**
- 날짜: 2026-06-05

> ⚠️ **정정(2026-06-05 같은 날)**: 센서 백엔드가 valid_min/max 를 *다시* 요구(정상 센서의 raw 글리치 1개 컷 목적). 본 ADR 의 "valid_min/max 전면 제거" 는 무효가 되고 [ADR-0015](0015-정상범위-재도입-3축-입력전송만.md)가 재도입(펄스는 입력+전송만, 판정=백엔드). 단, 고장(dead)/임계값(level) 축 정의 자체는 그대로 유효하며 0015 의 3축 모델에 포함됨.
- 결정자: (사용자 / Claude Code)
- 관련: [ADR-0013](0013-이상치-유효범위-펄스-판정.md)(대체함), [ADR-0010](0010-현장-블라인드-노드-수신-중심-v2.md)(판정=백엔드 원칙 복원), `src/lib/backendApi.js`(`sensorStatusPath`), `src/lib/store.jsx`(`setSensorLifecycle`), CHANGELOG `[Unreleased]`

## 맥락

ADR-0013 은 같은 날 펄스가 센서별 유효범위(valid_min/max)를 로컬 설정·이상치 표시하고, 백엔드(`POST /nodes` 재전송)로 `valid_min`/`valid_max` 를 갱신하도록 했다. 그러나 백엔드 측에서 모델을 재검토한 결과, **유효범위(valid_min/max/spike) 계약 자체를 되돌리기로** 결정했다. 범위 기반 판정은 임계값(경보)과 개념이 겹치고, "정상범위 밖 = 자동 invalid" 가 평균·상태 계산을 복잡하게 만들기 때문이다.

## 결정

품질·이상을 **두 축으로 단순화**하고, 정상범위(valid_min/max)는 펄스·웹·백엔드에서 전면 폐기한다.

1. **고장(dead) 축 — 센서 생명주기.** 물리적으로 죽은 센서는 펄스가 `PATCH /api/pulse/v1/sensors/{sensor_code}` body `{"status":"dead"}` 로 보고한다(이미 구현된 `setSensorLifecycle` 경로 그대로). 백엔드는 dead 센서를
   - **노드 평균에서 제외**하고 나머지 정상 센서 평균으로 대체,
   - **offline 감지에서 제외**(sticky).
   복구 시 `{"status":"active"}`. 평균 응답에 **`excluded_sensors`**(고장으로 빠진 센서)를 포함한다.
2. **임계값(level) 축 — 위험값 경보.** 위험 판정은 기존 임계값(level1/level2)이 담당하며 이는 **프론트(웹)의 책임**이다. 값은 살려두고(드롭/보정 없음) 알람만 띄운다.
3. **펄스 = 정직한 raw 전송**(ADR-0010 원칙 복원). 이상치·결측 품질 판정은 백엔드 전담으로 되돌린다.

## 결과

- 좋은 점: 모델이 단순해지고(고장/임계값) 책임 경계가 명확해짐 — 펄스=raw, 프론트=경보, 백엔드=평균·품질. 원본 무결성 원칙과 충돌하던 "범위 밖 자동 invalid" 가 사라짐.
- 검증: 렌더러 빌드 0 에러, E2E 26/26 통과(정상범위 4테스트 제거 후). 고장 보고(PATCH dead) 경로는 손대지 않았고 기존 테스트 통과.
- 트레이드오프: 수집 단계에서 범위 이탈을 즉시 눈으로 보던 보조 표시가 사라짐 — 대신 임계값 경보(프론트)와 백엔드 품질 판정에 의존.

## 대안

- **ADR-0013 유지(정상범위 로컬+전송)**: 백엔드가 계약을 되돌려 전송 대상이 사라짐 — 기각.
- **정상범위 로컬 표시만 남기고 전송만 제거**: 판정 개념이 임계값과 중복되고 코드 표면만 남아 혼란 — 사용자 결정으로 전부 제거.
