# 작업 보고서 - 정상범위(valid_min/max) 폐기 → 고장(dead)+임계값(level) 두 축

**날짜**: 2026-06-05
**Phase**: Phase 4 (백엔드 API) — 계약 재정의
**작업자**: Claude Code
**소요 시간**: 약 40분

## 작업 목표

백엔드 모델 재정의(정상범위 계약 되돌림)에 맞춰, 펄스에서 정상범위(valid_min/max) 관련 코드를 전송·로컬표시까지 전부 제거하고 고장(dead)+임계값(level) 두 축 모델로 단순화한다.

## 배경

같은 날 ADR-0013 으로 추가했던 "펄스가 센서별 유효범위(valid_min/max)를 로컬 설정·이상치 표시·백엔드 전송" 기능을, 백엔드가 valid_min/max/spike 계약을 되돌리면서 폐기. 새 규칙:

- **고장(dead)**: 펄스가 `PATCH /sensors/{sensor_code} {status:"dead"}` 보고 → 백엔드가 노드 평균·offline 감지에서 자동 제외(평균 응답에 `excluded_sensors`), 복구 시 `{status:"active"}`. (펄스 기존 `setSensorLifecycle` 경로가 이미 이 계약과 일치 — 손대지 않음)
- **임계값(level)**: 위험값 경보는 level1/2 가 담당하며 프론트(웹) 책임. 값은 살려두고 알람만.
- 펄스 = 정직한 raw 전송, 품질(이상치·결측) 판정 = 백엔드 전담(ADR-0010 원칙 복원).
