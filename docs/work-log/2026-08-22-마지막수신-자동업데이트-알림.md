## ① 마지막 수신 정확도

**문제**: `lastRx` 가 파일 저장시각(mtime)이었다. 덮어쓰기 로거는 데이터가 끊겨도 mtime 을 갱신하므로 **끊긴 노드가 "수신중"으로 보였다**. 값 출처도 경로마다 달랐다.

**해결**:
- `folderService.buildDetectedFile` — 파일 안 첫/마지막 유효 타임스탬프를 파싱해 `periodStart`/`periodEnd` 채움 (기존 TODO 자리)
- `folderApi.scanFolder` — `dataStart`/`dataEnd` 로 매핑, `modified`(mtime)와 명확히 분리
- `store.applyFileTimes` — `lastRx`(=dataEnd) / `lastFileWrite`(=mtime) 분리. **dataEnd 없으면 null, mtime 폴백 안 함**
- `refreshFiles` — **매 스캔마다 갱신** (전송 성공에만 의존하던 것 수정)
- `loadNodesFromBackend` — **내 파일이 있으면 내 파일 우선**, 없는 노드만 백엔드 `last_seen` 폴백
- 등록 위저드 / 자동 임포트 — mtime 시드 제거
- 드로어 — `마지막 데이터` · `파일 저장` 나란히 표시 + 진단 로그에 "로거는 도는데 값이 안 들어옴" 문장 추가

**실측 검증** (감시폴더 실파일):
```
80053.txt        데이터 ~2026-06-01   파일저장 2026-06-01 11:25
90030.txt        데이터 ~2026-06-10   파일저장 2026-06-10 09:27
W-3.txt          데이터 없음          → null (mtime 으로 안 때움)
```

## ③ 알림 (디스코드 + 이메일)

백엔드에 이미 있던 것: heartbeat 엔드포인트, 수집기/노드 오프라인 감지, 인앱 알림(DB+SSE), SMTP.
**빠진 것은 외부 채널 발송과 일일 요약뿐이었다.**

**백엔드** (`yuhyun-sensor-back`):
- `OutboundService` — 디스코드 웹훅(심각도별 색) + 이메일. **`emit()` 한 곳에 팬아웃** → 기존/신규 알림이 자동 포함
- `DailyReportService` — 매일 KST 지정 시각(기본 8시) 요약. **문제 없어도 발송**
- 점검 엔드포인트 3개 (`outbound/config`, `outbound/test`, `daily-report/run`)

**Pulse**:
- `sendHeartbeat` (메인) + `pulse:heartbeat` IPC + `App.jsx` 60초 루프
- PC 가 죽으면 스스로 알릴 수 없으므로 **서버가 침묵을 감지**하는 구조

## 알려진 이슈

- 전 노드의 기록 간격이 1440분(위저드 기본값) → 판정 임계 36시간/72시간. **이틀 무수신도 "수신중"**. 실제 간격으로 조정 필요 (80053 은 실제 1시간)
- 전송 타임스탬프에 시간대 표기 없음 — 백엔드가 KST/UTC 중 무엇으로 읽는지 **미확인**
- `lastSyncAt`·노드 상태는 여전히 메모리 (Phase 2 SQLite)
- 매 스캔마다 파일 전체를 훑어 마지막 유효 행을 찾음 — 덮어쓰기 전제. 누적형 파일 유입 시 역방향 부분 읽기로 전환 필요
