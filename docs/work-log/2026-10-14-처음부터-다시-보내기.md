# 작업 보고서 - 처음부터 다시 보내기 버튼

**날짜**: 2026-10-14  
**Phase**: Phase 4~5 (백엔드 연동 · 동기화) 기능 추가  
**작업자**: Claude Code  
**소요 시간**: 약 1시간

## 작업 목표

서버에 빠진 데이터가 있을 때, 원본 .txt 나 노드를 건드리지 않고 파일 전체를 다시 보내 빈 곳을 채운다.

## 배경

펄스는 마지막 전송 시각 뒤의 행만 보낸다. 그보다 앞선 시각이 서버에 빠져 있으면 다시 보낼 방법이 없었다.

- 메모장(.txt)을 고쳐도 다시 올라가지 않는다. 펄스는 줄의 시각만 본다.
- 노드 삭제 후 재등록은 그 노드의 서버 데이터를 지운다.

## 구현된 기능

- 노드 상세 → 전송 큐 → **처음부터 다시 보내기**. 파일 전체를 한 번 보낸다.
- 서버에 없는 시각만 채워지고, 이미 있는 값은 바뀌지 않는다(서버 ingest 가 같은 시각을 무시).
- 결과 알림: "파일 전체 N행을 다시 보냈습니다 · 새로 채워진 값 M건". 빠진 게 없으면 그렇게 알려 준다.
- 실패하면 "다시 보내기 실패"만 알리고 버퍼·워터마크는 그대로 둔다.
- 다시 보낸 뒤 평소 전송은 다시 새 행만 본다.

### 같이 고친 것

- 노드 상세의 탭이 저절로 "채널 스트림"으로 돌아가던 문제. 노드 값이 갱신될 때마다(버튼 클릭, 60초 자동 확인) 탭이 처음으로 튀었다. 새 버튼을 누르면 결과를 보기도 전에 탭이 바뀌어서 같이 고쳤다.

## 알려진 이슈

- 실서버로는 눌러 보지 않았다. 서버 응답의 `inserted` 를 읽는 부분(메인 프로세스)은 자동 테스트가 덮지 못한다.
- 파일에 남아 있지 않은 행은 못 채운다.
- 서버에 그 시각이 빈 값(결측)으로 이미 있으면 안 바뀐다. 관리자 화면의 측정값 수정에서 넣어야 한다.
- 파일 전체를 센서마다 요청 하나로 보낸다. 아주 큰 파일은 오래 걸리거나 실패할 수 있다(최초 등록 백필과 같은 경로).
- 센서가 전부 비활성이면 아무것도 안 보내고도 "빠진 값이 없었습니다"라고 나온다.
