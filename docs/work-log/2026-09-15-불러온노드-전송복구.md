# 작업 보고서 - 서버에서 불러온 노드 전송 복구

**날짜**: 2026-09-15  
**Phase**: Phase 4~5 (백엔드 연동 · 동기화 워커) 버그 수정  
**작업자**: Claude Code  
**소요 시간**: 약 40분

## 작업 목표

서버에서 불러온 노드가 "전송 완료"로 보이면서 실제로는 전송이 멈춰 있던 문제를 고친다. 다시는 조용히 멈추지 않게 한다.

## 원인

1. 백엔드 개편(2026-06) 뒤로 `GET /api/pulse/v1/nodes` 응답에 **노드 단위 `sensor_type` 이 없다.** 종류는 채널(센서)에만 있다.
2. `normalizeBackendNode` 는 노드 `sensor_type` 만 읽는다. 그래서 불러온 노드의 `sensorType` 이 `''` 가 된다.
3. `syncNode` 는 `!node.sensorType` 이면 `{ skipped: true }` 만 돌려주고 **상태를 바꾸지 않는다.**
4. `loadNodesFromBackend` 는 불러온 노드에 `transmit: 'sent'` 를 **무조건** 붙였다. 그래서 화면은 계속 "전송 완료"였다.
5. `App.jsx` 는 앱이 시작할 때마다 서버에서 노드를 불러온다. 그래서 등록 창으로 다시 등록해 종류를 채워도 **재시작하면 다시 멈췄다.**

실사용 영향: 80053·80181·80225·80241·80224. 백엔드는 노드 응답에 대표 종류를 다시 넣도록 따로 수정했다. 펄스 쪽 수정은 백엔드 응답 형식이 또 바뀌어도 조용히 멈추지 않게 막는 방어다.

### 수정된 파일
- `src/lib/store.jsx`
  - `loadNodesFromBackend`: `sensorType = n.sensorType || pickRepresentativeType(n.channels)` 로 채운다. 이 값을 **`resolveSensors` 호출 전에** 쓰고 `buildNode` 에도 넘긴다. 종류에 따라 센서 구성이 달라지기 때문이다(깊이형·다채널 원시).
  - `loadNodesFromBackend`: `transmit: 'sent'` 고정값을 지웠다. 기본값은 `'queued'` 이고 첫 `syncNode` 가 상태를 판정한다.
  - `syncNode`: 전제조건을 못 갖추면 `transmit: 'failed'` 와 `txIssue` 에 사유를 기록한다. 사유는 원본 파일 없음 / 계측기 종류 미지정 / 센서 구성 없음 중 하나다.
  - `syncNode`: 새 행이 없으면 `transmit: 'sent'` 로 확정한다. 전송에 성공하거나 실패하면 `txIssue` 를 지운다.
  - `buildNode`: `txIssue: null` 필드를 추가했다.
- `src/components/ui/StatusPill.jsx` — `TxPill` 에 `issue` 속성을 추가했다. 값이 있으면 빨간 "전송 불가" 핀을 보여주고, 사유는 `title`(마우스 오버)로 보여준다.
- `src/components/nodes/NodeTable.jsx`, `NodeCardGrid.jsx`, `NodeCompactList.jsx`, `src/pages/TransmitQueue.jsx` — `issue={n.txIssue}` 를 넘긴다.
- `src/components/nodes/NodeDetailDrawer.jsx` — 전송 탭에 사유 문장을 표시한다.
- `CHANGELOG.md` — `[Unreleased] > Fixed` 에 항목을 추가했다.

## 알려진 이슈

- 전송 큐의 "재전송 / 버퍼 비우기 / 전체 재전송"은 여전히 메모리 시뮬레이션이다(`retryNode` 등이 `transmit: 'sent'` 로 바꿈). 다만 `txIssue` 는 지우지 않으므로 "전송 불가" 표시는 남는다. 상태도 다음 자동 확인(1분 이내) 때 다시 판정된다.
- 서버에서 불러온 직후부터 첫 자동 확인(최대 1분)까지는 "버퍼 대기"로 보인다. 아직 안 보냈으니 정직한 표시다.
- 이어서 보낼 시작점은 여전히 서버 `last_seen` 이다(`store.jsx` `lastSentTs: n.lastRx`). `last_seen` 이 측정 데이터 시각이 아니면 빠진 구간이 생길 수 있다. 백엔드 쪽 확인이 필요하다.
