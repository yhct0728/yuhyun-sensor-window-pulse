# 채널 코드 접두 = 채널 sensor_type 표준 약어 (90030 GI→GW 근본수정)

- 날짜: 2026-06-10
- 관련: [ADR-0018](../decisions/0018-채널코드-접두가-채널종류를-따라감.md), [ADR-0017](../decisions/0017-채널별-sensor-type-노드내-종류혼재.md)
- 요청: 센서 백엔드 표준화 — 코드 약어를 sensor_type 표준 약어와 일치(등록·측정 양쪽), 접미 번호 보존

## 배경

한 노드(시추공)에 종류가 섞이면 채널 코드 약어가 종류와 어긋났다. 실사례 `90030`: 1번 채널이 실제 지하수위계인데 노드 대표(지중경사계 GI)에 휩쓸려 `90030-GI-1` 로 등록(나머지 GI-2~21 은 정상). 백엔드 ingest 는 `sensorCode` 로만 센서를 찾으므로(측정 payload 에 종류 없음) 코드↔종류 불일치 시 매칭 실패 → 데이터 유실.

## 진행 방식 (요청대로 단독 적용 금지 → 검토·제안 후 승인받아 구현)

1. **약어표 검토**: 백엔드 표준 14종을 펄스 `SENSOR_TYPES.ch` 와 대조.
   - 결론: **전부 일치.** 백엔드가 펄스의 기존 약어(SP/BT/LC/EQ 포함)를 표준으로 채택 → **약어표 자체는 펄스 수정 불필요.**
   - 사용자 확정: GI/GW/WL… 일치, 남은 코드 작업은 90030 GI→GW 뿐.
2. **근본 원인 규명**: 약어표가 아니라 **코드 접두를 노드 대표 종류에서 뽑는 것**이 원인(`resolveSensors` `prefix = sensorChannelCode(sensorType)`). 채널별 `sensor_type`(ADR-0017)은 보냈지만 코드는 노드 종류 고정 → 불일치.
3. **수정 방안 제시 → 승인**: "접두가 채널 자신의 종류를 따라가게(B)" 포함 확정.

## 변경 (TDD)

- `src/lib/sensorModel.js` `resolveSensors`:
  - `opts.channelTypes`(키=`seq` 1-based) 추가. 채널 종류 = **명시 override > 헤더 코드 추론(`guessSensorTypeFromCode`) > 노드 대표(폴백).**
  - 코드 = `{sensorChannelCode(chType)}-{seq}`. 각 센서에 `seq`/`sensorType` 부착. 접미 번호(seq) 보존 = 도면 위치 유지.
- `src/components/nodes/RegisterWizard.jsx`:
  - `chTypes` 를 **코드 키(불안정) → seq 키(안정)** 로 전환, `channelTypes` 로 `resolveSensors` 에 전달 → 종류 변경 시 코드 즉시 재생성.
  - 등록 `channels[]` 는 같은 센서 객체의 `code`+`sensorType` 를 실어 약어↔종류 구조적 일치. `chTypeFor`/`guessSensorTypeFromCode` 직접 사용 제거(해석기로 일원화).

## 범위 제외 (의도)

- **노드 상세 드로어의 기존 노드 종류 변경 → 코드 리네임 안 함**: 등록된 노드 코드는 백엔드가 정본 → 리네임 = 백엔드 동시 정정 필요.
- **깊이형 단일 센서 코드(A/P 축문자)**: 약어 통일 여부 별도 합의.

## 후속 (코드 외 — 조율, 단독 선반영 금지)

- `90030` 전환: 펄스 GW-1 재등록 ↔ 백엔드 `90030-GI-1→90030-GW-1` 리네임(내부 id 유지=과거 데이터 보존)을 **동시 배포**. ⚠️ `sensor_sync:'replace'` 가 사라진 GI-1 을 정리하려 들어 경합 가능 → 순서(백엔드 리네임 先 → 펄스 송신) 합의.
