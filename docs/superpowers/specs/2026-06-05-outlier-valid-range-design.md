# 이상치 유효범위 — 설계안

- 작성일: 2026-06-05
- 상태: 승인 대기
- 관련: ADR-0010(현장-블라인드/판정=백엔드) — **본 기획은 이 원칙을 일부 변경함**(아래 "결정 배경" 참조)

## 한 줄 요약

센서(채널)별로 정상 범위(하한~상한)를 입력해두고, raw 값이 그 범위를 벗어나면
**🔴 이상치로 표시만** 한다. 값은 버리거나 고치지 않고 그대로 전송한다.

## 결정 배경

기존 원칙(ADR-0010, 메모리)은 "Pulse = 정직한 raw 전송, 이상치·품질 판정 = 백엔드(GeoMonitor)
전담"이었다. 이번 기획에서 사용자는 **판정 주체를 Pulse 로 변경**하기로 결정했다.
따라서 Pulse 가 유효범위를 보관하고, 전송 전 raw 값을 그 범위와 비교해 이상치 여부를 판정한다.

이 변경은 별도 ADR(예: `docs/decisions/NNNN-이상치-판정-펄스이관.md`)로 기록하고,
ADR-0010 의 관련 문구 상태를 갱신한다. (구현과 무관하게 문서만 정리)

## 확정된 결정 (브레인스토밍 결과)

| 항목 | 결정 |
|---|---|
| 판정 주체 | **Pulse(이 앱)가 직접** 판정 |
| 설정 단위 | **센서(채널) 개별 입력만**. 종류별 기본값 페이지는 만들지 않음(범위 제외) |
| 범위 밖 값 처리 | **표시만(비파괴)**. 버리지 않고, 0 으로 바꾸지 않고, 원본 .txt 도 안 건드림 |
| 미입력 시 | **검사 안 함**(제로 디폴트). 처음엔 어떤 범위도 강제되지 않음 |
| 이상치 표시 위치 | 노드 상세 드로어 채널 행 + **노드 목록 요약 배지** |
| 저장 | 현 단계 메모리(store) + 임시 localStorage, Phase 2 에서 SQLite 이관 |

## 적용 대상 값

각 채널은 이미 최근 값 `value:number|null` 과 `unit:string` 을 보유한다(`lib/types.js`).
유효범위는 **이 `value`(전송되는 바로 그 숫자)** 에 적용한다. 새로운 계산·공식 적용은 없다.
(Pulse 는 공식을 적용하지 않음 — ADR-0009 유지. 따라서 범위 단위는 .txt 가 담고 있는 그 값의
단위이며, 화면에는 채널 `unit` 을 그대로 표기한다.)

## 컴포넌트 / 화면

### 1. 노드 상세 드로어 — 채널 행에 범위 입력 추가 (유일한 입력 지점)

`components/nodes/NodeDetailDrawer.jsx` 의 채널 스트림 탭(또는 채널 목록 영역)에 칸 추가.

```
┌─ YH-0007 상세 ─ 채널 ─────────────────────────────────┐
│ 채널    최근값      정상범위 (하한~상한)    상태        │
│ WL-1    4.2 m       [ 0 ] ~ [ 10 ]  m       정상        │
│ WL-2    12.8 m      [ 0 ] ~ [ 10 ]  m      🔴 이상치    │
│ GI-A    -41 mm      [-30] ~ [ 30 ]  mm     🔴 이상치    │
│ TMP-1   23 ℃        [   ] ~ [    ]  ℃       —(검사안함)  │
└───────────────────────────────────────────────────────┘
```

- 하한/상한 숫자 입력 2칸, 단위는 입력칸 옆에 읽기전용 표시.
- 한쪽만 입력해도 됨(예: 상한만). 둘 다 비면 "검사 안 함".
- 입력은 즉시 저장(블러/엔터). 빈 입력 = 해당 경계 해제.
- 잘못된 입력(하한 > 상한, 숫자 아님)은 인라인 경고, 저장 거부.

### 2. 이상치 판정 — 순수 함수 한 곳

`lib/outlier.js` 신설.

```js
// 범위가 없으면(둘 다 null) 판정하지 않음 → null 반환(= 검사 안 함)
// value 가 null 이면 미수신 → null 반환
// 그 외: value < min(있을 때) 또는 value > max(있을 때) → true
export function isOutlier(value, range) { /* ... */ }
```

- 어디서도 직접 비교하지 않고 이 함수만 호출(단일 소스).
- 값/범위 변형 없음 — 순수 판정만.

### 3. 노드 목록 요약 배지

`components/nodes/NodeTable.jsx` / `NodeCardGrid.jsx` / `NodeCompactList.jsx`(3종 뷰)에
노드 단위 이상치 개수 배지("이상치 N") 표시. 노드의 채널들을 `isOutlier` 로 집계.

## 데이터 구조

채널별 범위를 채널 객체 또는 별도 맵에 보관.

```
// 범위 타입
range: { min: number|null, max: number|null }   // 둘 다 null = 검사 안 함

// 보관 위치(택1, 구현 단계에서 확정):
//  A. Channel 에 range 필드 추가 (lib/types.js Channel typedef 확장)
//  B. store 에 { [nodeId-channelCode]: range } 맵
// → 영속 키가 노드-채널이라 B 가 Phase 2 SQLite 이관에 자연스러움.
```

- 임시 영속: localStorage 키 1개(예: `pulse:channelRanges`) — 다크모드/sensorTypes 와 동일한
  Phase 1 임시 패턴. Phase 2 에서 SQLite 로 이관.

## 비범위 (이번에 안 하는 것)

- 종류별 기본값 페이지(새 사이드바 메뉴) — 만들지 않음.
- 경고/주의 다단계 등급 — 이상치 1단계만.
- 이상치 값 자동 제외/보정/드롭 — 절대 안 함(표시만).
- 백엔드로 범위·이상치 플래그 전송 — 이번 범위 밖(추후 결정).

## 데이터 흐름 (요약)

```
.txt raw → 채널 value 갱신 → isOutlier(value, range)
        → true 면 드로어 행 🔴 + 노드 목록 요약 +1
        → 전송: value 그대로(비파괴), 표식만 동행 가능
```

## 테스트 관점

- `lib/outlier.js` 단위 판정: 범위 없음/한쪽만/양쪽, value=null, 경계값(== min/max), 역전 범위.
- 드로어: 범위 입력 → 즉시 상태 반영, 잘못된 입력 거부, "검사 안 함" 표시.
- 노드 목록: 이상치 개수 집계 정확성, 0 일 때 배지 없음.
- 기존 E2E(드로어 8 / 대시보드 6) 회귀 없음.
